- Index Explore 패턴 (벡터 DB 없이!)

마지막에 `questions.md`에 있는 10개의 질문 중 원하는 것들로 챗봇을 테스트하고, 정답과 일치할 때까지 프롬프트/로직을 개선하는 게 목표입니다.

## 🔑 핵심 제약 — Index Explore 방식

**❌ 금지사항:**
- 모든 문서를 한꺼번에 프롬프트에 넣고 질문하기 (context overflow)
- 단순 키워드 검색 후 매칭된 파일 전체를 통째로 LLM에 넣기
- 벡터 DB (FAISS, Qdrant 등) 사용 ← 이 과제는 index explore 연습용

**✅ 권장 방식 (Index Explore 패턴):**
1. LLM에게 **문서 목록(파일명 + 한 줄 요약)** 만 먼저 제공
2. LLM이 Tool Call로 **"읽고 싶은 문서"** 를 선택
3. 선택된 문서 내용을 읽어서 LLM에 다시 제공
4. LLM이 답을 찾으면 최종 응답, 아직 정보가 부족하면 다른 문서 추가 요청
5. Agentic Loop로 이 과정 반복

이 패턴이 왜 중요한가?
- 컨텍스트 비용 절감
- 관련 없는 정보로 인한 노이즈 최소화
- 실제 production RAG의 핵심 기법
- **LLM이 "검색 주체"가 되는** 진짜 agentic 방식

## 🛠️ 구현 가이드 (코드는 직접 작성)

### Step 1. 문서 인덱스 만들기

먼저 `docs/` 폴더를 스캔해서, 각 문서의 **간단한 메타데이터**를 만드세요.
- 파일명
- 한 줄 요약 (첫 줄 제목, 혹은 직접 작성)

이 인덱스가 LLM에게 "어떤 문서들이 있는지" 알려주는 역할을 합니다.

> 💡 팁: 요약을 LLM에게 자동 생성하게 해도 좋고, 수작업이어도 OK.
> 요약이 너무 길면 LLM이 거기서 답을 찾아버려서 의미가 없어집니다. 한 줄로!

### Step 2. Tool 정의

최소 2개의 tool을 만드세요:

**Tool 1: `list_documents()`**
- 설명: 사용 가능한 모든 문서의 목록(파일명 + 요약)을 반환
- 파라미터: 없음
- 반환: 문자열 (markdown 형식 추천)

**Tool 2: `read_document(filename)`**
- 설명: 특정 문서의 전체 내용을 읽는다
- 파라미터: `filename` (string)
- 반환: 해당 문서의 markdown 내용

> 💡 고급: `search_documents(keyword)` tool도 추가하면 더 효율적일 수 있지만,
> 필수는 아닙니다. LLM이 목록만 보고도 꽤 잘 찾습니다.

### Step 3. System Prompt

챗봇의 system prompt에는 다음을 포함하세요:
- 역할 정의 (사내 위키 QA 챗봇)
- **"먼저 list_documents로 전체 목록을 보고, 관련 있어 보이는 문서만 read_document로 읽어라"**
- **"최신 정보를 우선하라 (2025 > 2024, v2 > v1)"**
- **"추측하지 말고 문서에 명시된 내용만 답하라"**
- **"답을 찾았으면 출처 문서명을 함께 제시하라"**

### Step 4. Agentic Loop

while 루프로 다음을 반복:
1. LLM 호출 (messages + tools)
2. 응답에 `tool_calls`가 있으면 → tool 실행 → 결과를 messages에 추가 → 다시 1번
3. `tool_calls`가 없으면 → 최종 답변을 사용자에게 출력 → 종료
4. 최대 iteration 제한 (예: 10회)을 두어 무한 루프 방지

이 구조는 `day2/03_agent_v2/challenge/solve.py` 과제의 패턴과 유사합니다.

### Step 5. 테스트 & 개선

`questions.md`의 질문들을 챗봇에게 물어보고, 정답과 비교하세요.

**실패하는 경우 자문해볼 것:**
- LLM이 관련 문서를 못 찾았나? → index의 요약을 더 명확하게
- 관련 문서는 읽었는데 오답이다? → system prompt 강화 (추측 금지, 최신 우선)
- outdated 문서를 참조했다? → "최신 정보 우선" 규칙을 강조
- 여러 문서를 못 연결했다? → "답이 여러 문서에 걸쳐 있을 수 있다" 힌트
- 노이즈 문서에 낚였다? → 문서 요약을 더 정확하게

## 🙋 자주 묻는 질문

**Q. 파이썬 말고 다른 언어로 해도 되나요?**
A. 네, 자유입니다. 다만 OpenAI 호환 API를 쉽게 호출할 수 있는 언어여야 합니다.

**Q. UI도 만들어야 하나요?**
A. 필수 아닙니다. 터미널에서 `input()` 으로 질문 받고 `print()` 로 답하면 충분합니다.
   여유가 있으면 Gradio, Streamlit 같은 걸로 UI 만들어도 좋습니다.

**Q. 벡터 임베딩을 써도 되나요?**
A. 이 과제의 취지는 "LLM이 직접 index를 탐색"하는 것입니다. 벡터 검색은 쓰지 마세요.
   (실제 production에서는 벡터+index 하이브리드가 보통이지만, 여기서는 index explore만.)

**Q. 채점은 어떻게 하나요?**
A. **채점 없습니다.** `questions.md`의 정답과 비교하며 **스스로** 개선하는 것이 목표입니다.
   실제 현업에서 RAG를 개선하는 프로세스를 체험하는 게 핵심입니다.

**Q. 시간이 남으면?**
A. 다음을 시도해보세요:
   - 이어지는 질문 처리 (multi-turn 대화 기록 유지)
   - 출처 문서의 해당 줄 번호까지 정확히 인용
   - "문서에 없는 정보입니다" 같은 겸손한 답변 구현
   - 문서를 추가해서 챗봇이 여전히 잘 동작하는지 확인
