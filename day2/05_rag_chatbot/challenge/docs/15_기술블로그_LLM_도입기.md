# [기술블로그] 우리가 Qwen3-32B를 도입한 이유

작성자: 이승민 (CTO)
2025-04-08

뉴럴웍스는 2025년 Q2부터 베이스 LLM으로 **Qwen3-32B**를 도입했습니다.
이 글은 왜 이 모델을 선택했는지, 어떤 트레이드오프가 있었는지 공유합니다.

## 배경
기존에는 자체 파인튜닝한 소규모 모델(7B)을 사용했지만, NovaChat v2의 32k context 요구와 멀티랭귀지(한/영) 지원을 위해 더 큰 베이스 모델이 필요했습니다.

## 후보 비교
| 모델 | 장점 | 단점 |
|-----|-----|-----|
| Llama3-70B | 생태계 풍부 | 한국어 약함, 비용 ↑ |
| GPT-4 API | 품질 최상 | 비용 ↑↑, 온프렘 불가 |
| Mixtral 8x7B | 속도 빠름 | 한국어 데이터 부족 |
| **Qwen3-32B** | **한국어 양호, 비용 효율, 오픈 가중치** | 일부 영어 태스크 성능 ↓ |

## 선택 이유
1. **사내 한국어 데이터로 파인튜닝 가능** (핵심)
2. **비용 효율** — 70B 대비 추론 비용 50% 수준
3. **온프렘 배포 가능** (데이터 보안 요구사항)
4. **32k context 네이티브 지원**

## 파인튜닝 과정
- 데이터: 사내 CS 로그 50만 건 + 공개 한국어 코퍼스
- 방법: LoRA (r=16, alpha=32)
- 학습 GPU: H100 4대, 약 3일 소요
- 결과: NovaChat v1 대비 한국어 답변 품질 +23% (내부 평가 기준)

## 한계와 다음 단계
- 영어 코드 생성은 여전히 Llama3 대비 약함 → 하이브리드 라우팅 검토 중
- Tool use 성능 개선 필요

## 결론
"한국어 특화 + 비용 효율 + 온프렘 배포 가능"의 세 가지 조건을 모두 만족하는 유일한 선택지였습니다.
