OIDC — OAuth2와 무엇이 다른가?

OAuth2 위에 "사용자가 누구인지"를 추가한 프로토콜입니다

OAuth2

1. /authorize → 로그인
2. callback?code=
3. POST /token → access_token
4. GET /userinfo ← 추가 호출 필요!
요청 4번 — 마지막에 API를 한 번 더 호출해야 합니다

OIDC (OpenID Connect)

1. /authorize → 로그인 (+ nonce!)
2. callback?code=
3. POST /token → access_token + id_token
→ JWT 디코딩만 하면 끝!
요청 3번 — id_token 안에 사용자 정보가 이미 들어있습니다
OIDC의 핵심: nonce 파라미터를 보내야 id_token이 발급됩니다. nonce가 없으면 id_token이 안 옵니다!
SSO

왜 이 개념을 알아야 하는가?

사내 OAuth2/OIDC 구현은 표준과 살짝 다릅니다.
AI에게 "OAuth2 로그인 만들어줘"라고만 하면 100% 에러가 납니다.

SSL 인증서

표준: 공인 CA
사내: 자체 인증서
→ AI는 verify=True로 짜줌
→ 연결 거부

Client Secret

표준: 긴 시크릿 필수
사내: 빈 문자열
→ AI는 시크릿을 넣어줌
→ 인증 실패

id_token 발급

표준: scope만으로 발급
사내: nonce 필수
→ AI는 nonce를 안 넣음
→ 토큰 없음

결론: 프로토콜의 원리를 이해해야 AI에게 "우리 환경은 이렇게 다르다"고 정확히 설명할 수 있고, 바이브 코딩이 한 번에 성공합니다.

과제 1: OAuth2 로그인

사용할 API 엔드포인트
단계URL / 방법
1. 인가 요청GET https://a2g.samsungds.net:8090/oidc/authorize
2. 콜백 수신GET http://localhost:3000/callback?code=... (내가 만드는 서버)
3. 토큰 교환POST https://a2g.samsungds.net:8090/oidc/token
4. 사용자 정보GET https://a2g.samsungds.net:8090/oidc/userinfo
인증 정보
client_id: cli-default
client_secret: "" (빈 문자열)
redirect_uri: http://localhost:3000/callback
scope: openid
response_type: code
주의사항
• SSL: verify=False (사내 인증서)
• Basic Auth: password를 빈 문자열로
• token 응답에서 access_token 추출
• userinfo 호출 시 Bearer 헤더
성공: 본인의 이름(한글)과 부서명(한글)을 POST https://a2g.samsungds.net:70777/challenges/sso_oauth2/submit에 제출
{"token":"access_token", "answer":{"name":"홍길동","dept":"개발팀"}} → 🎉 대시보드에 이름 표시

과제 2: OIDC 로그인

OAuth2와 동일한 엔드포인트를 쓰되, /userinfo 호출 없이 id_token에서 직접 이름/부서를 추출하세요.

OAuth2와 다른 점
항목변경
scopeopenid → openid profile email
authorize 파라미터nonce 추가 (UUID로 생성, 필수)
token 응답access_token + id_token (JWT)
사용자 정보/userinfo 호출 안 함 → id_token을 JWT 디코딩
JWT 디코딩jwt.decode(id_token, options={"verify_signature": False})
claimsname = 한글 이름, dept = 한글 부서명
성공: id_token에서 추출한 이름과 부서명을 POST /challenges/sso_oidc/submit에 제출
{"token":"access_token", "answer":{"name":"홍길동","dept":"개발팀","method":"oidc"}} → 🎉 대시보드에 이름 표시

 1# 화이트리스트 기반 명령어 필터
 2ALLOWED_COMMANDS = {"ls", "cat", "grep", "find", "head",
 3                    "wc", "python", "pip", "git"}
 4BLOCKED_PATTERNS = ["rm -rf", "sudo", ":(){:|:&}", "dd if="]
 5ALLOWED_DIR = "/home/user/workspace"
 6
 7def validate_command(cmd: str) -> bool:
 8    # 1. 위험 패턴 차단
 9    for pattern in BLOCKED_PATTERNS:
10        if pattern in cmd:
11            return False
12
13    # 2. 첫 번째 명령어가 허용 목록에 있는지
14    base_cmd = cmd.split()[0].split("/")[-1]
15    if base_cmd not in ALLOWED_COMMANDS:
16        return False
17
18    # 3. 경로 이탈 방지
19    if ".." in cmd or cmd.startswith("/"):
20        return False
21    return Truepython
